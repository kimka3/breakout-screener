# 120일선 돌파 + 거래량 급증 스크리너

**S&P 500(약 500종목) + KOSPI 200(약 200종목)** 을 대상으로 다음 두 조건을 동시에 만족하는 종목을 찾습니다.

1. **120일 이동평균선 상향 돌파** — 전일 종가 ≤ 전일 MA120, 당일 종가 > 당일 MA120
2. **거래량 급증** — 돌파 당일 거래량 ≥ 직전 5거래일(1주일) 평균 거래량 × 2
3. **돌파 유지** — 현재가(기준 거래일 종가)도 여전히 MA120 위

## 설치

```bash
pip install yfinance pandas lxml
```

## 실행

```bash
python sp500_breakout.py
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--ma` | 120 | 이동평균 기간(거래일) |
| `--vol-window` | 5 | 직전 평균거래량 산출 기간(거래일) |
| `--vol-mult` | 2.0 | 거래량 배수 기준 |
| `--lookback` | 1 | 최근 N 거래일 내에 발생한 신호를 검색 |
| `--date` | 최신 | 기준일 `YYYY-MM-DD` (과거 시점 재현용) |
| `--price-basis` | adj | `adj`=수정주가 기준, `raw`=종가 그대로 |
| `--tickers` | - | 쉼표 구분 티커 목록 (테스트용) |
| `--refresh-list` | - | 구성종목 목록 강제 갱신 |
| `--out` | breakouts.csv | 결과 CSV 경로 |
| `--html` | - | 휴대폰용 HTML 리포트 생성 (경로 생략시 `report.html`) |
| `--no-cache` | - | 시세 캐시를 무시하고 새로 받기 |
| `--no-hold` | - | 3번 조건 해제 (돌파 후 밀려난 종목도 포함) |
| `--market` | all | `all` / `sp500` / `kospi200` |

예시:

```bash
python sp500_breakout.py --lookback 5 --vol-mult 1.5
```

## 휴대폰에서 보기

```bash
python sp500_breakout.py --lookback 20 --html
```

두 개의 HTML이 생성됩니다.

- `report.html` — 브라우저에서 바로 열 수 있는 단독 파일
- `report.artifact.html` — Claude Artifact 로 게시할 때 쓰는 조각 파일

게시하면 휴대폰 브라우저에서 열리는 링크가 나옵니다. 종목별로 지표 4칸, 최근 140거래일 주가/MA120 차트, 거래량 스트립(돌파일 봉만 주황색)이 들어가고 차트를 문지르면 그날 값이 표시됩니다. 카드/표 보기와 최근순/거래량배수순 정렬을 전환할 수 있습니다.

디자인이나 항목을 바꾸려면 `report_template.html` 을 고치면 됩니다. 스크립트가 `/*__DATA__*/null` 자리에 결과 JSON 을 주입하는 구조입니다.

시세는 `.cache/` 에 6시간 캐시되므로 리포트만 다시 뽑을 때는 재다운로드하지 않습니다.

## 자동 실행

GitHub Actions 가 매일 `21:57 UTC`(= 다음날 `06:57 KST`)에 스크리너를 돌려
결과를 `gh-pages` 브랜치로 배포합니다. PC 를 켜두지 않아도 갱신됩니다.

- 워크플로: `.github/workflows/daily-schedule.yml`
- 결과 페이지: https://kimka3.github.io/breakout-screener/
- 수동 실행: 저장소 **Actions** 탭 → **Daily breakout screen** → **Run workflow**

실행 시각은 미국장 마감(05:00 KST) 이후, 한국장 개장(09:00 KST) 이전이라
양쪽 시장 모두 전일 봉이 확정된 상태에서 스캔합니다.

분 단위를 정각에서 어긋내 둔 것은 의도적입니다. GitHub 예약 실행은 정각에
요청이 몰려 대기열이 길어지고, 그만큼 실제 실행이 밀립니다.

> 클라우드 실행은 GitHub Actions 만 가능합니다. Claude 클라우드 루틴은
> 아웃바운드 허용 목록에 패키지 저장소와 Anthropic API 만 있어
> 야후·네이버가 모두 `403 CONNECT` 로 막힙니다 (2026-09-03 확인).

## 설계 시 판단한 부분

- **"돌파"** 는 단순히 MA 위에 있는 상태가 아니라 *전일 아래 → 당일 위* 로 교차한 날만 잡습니다. 지속적으로 위에 있던 종목은 걸리지 않습니다.
- **"직전 1주일 평균거래량"** 은 돌파 당일을 **제외한** 직전 5거래일 평균입니다. (당일을 포함하면 급증분이 분모에 섞여 기준이 느슨해집니다.)
- **기준가**는 기본적으로 수정주가(Adj Close)를 씁니다. 액면분할·배당으로 생기는 인위적 갭이 가짜 돌파 신호를 만드는 것을 막기 위해서입니다. 표에 표시되는 `close` 는 실제 종가입니다. 원본 종가로 판정하려면 `--price-basis raw`.
- 거래량 배수는 `>=` 기준입니다. "2배 초과"로 엄격히 하려면 `--vol-mult 2.001` 처럼 주면 됩니다.
- **돌파 유지**는 *현재 시점에 MA120 위에 있는가*만 봅니다. 돌파 이후 한 번도 이탈하지 않았는지는 따지지 않습니다. `--lookback 1` 로 쓰면 돌파일이 곧 현재일이라 이 조건은 자동으로 충족됩니다.
- CSV 의 `last_close` / `last_above_ma_%` / `bars_since` 가 각각 현재가, 현재 이격률, 돌파 후 경과 거래일입니다.
- **시장은 따로 계산합니다.** 거래일 달력과 통화가 다르므로 기준 거래일·가격 표기(달러 2자리 / 원화 정수)를 시장별로 나눠 들고 갑니다. 리포트 상단 탭으로 전환합니다.
- **장중 미완성 봉은 제외합니다.** 해당 시장의 장 마감 시각 전이면 당일 봉을 버립니다. 거래량이 덜 쌓인 봉을 그대로 쓰면 거래량 급증 판정이 왜곡됩니다.
- **KOSPI 200 구성종목**은 네이버 금융에서 받습니다. `pykrx`(KRX 직접 조회)는 사내 프록시 인증서 검증에서 실패합니다.
- **KOSPI 종목은 후행 PER 이 없습니다.** 야후가 한국 종목에 trailingPE·EPS·섹터를 주지 않아 선행 PER 만 표시되고, 섹터 자리에는 시장명이 들어갑니다.
- **캐시 파일이 읽히지 않으면 새로 받습니다.** 사내 DLP 에이전트가 `.cache/` 의 CSV 를 암호화해 두는 일이 있어(헤더가 `SCDSA...` 바이너리로 바뀜) 읽기 실패를 캐시 미스로 처리합니다.
- **다운로드 실패 종목은 리포트에 표기합니다.** 야후가 대량 요청 중 일부 종목을 간헐적으로 거부하는데, 조용히 빠지면 신호를 놓쳐도 알 수 없습니다.
- **생성 시각은 한국 시간(KST)으로 찍습니다.** GitHub 러너는 UTC 라 `datetime.now()` 를 그대로 쓰면 9시간 어긋납니다.
- **기준 거래일**은 전 종목 마지막 봉의 *최빈값*으로 잡습니다. 최댓값을 쓰면 남들보다 하루 앞선 봉을 가진 한두 종목 때문에 헤더 날짜가 실제 데이터보다 앞서게 됩니다(2026-09-03 실행에서 실제 발생). 날짜가 다른 종목 수는 콘솔과 리포트 헤더에 표기됩니다.
- **PER** 은 조건을 통과한 종목에 대해서만 조회합니다(종목당 1회 요청). 500종목 전체를 받으면 느리고 차단당하기 쉽습니다. `per` 는 최근 12개월 실적 기준, `forward_per` 는 예상 실적 기준이며, 최근 12개월이 적자면 `per` 이 비고 `eps` 가 음수로 나옵니다 (리포트에는 "적자"로 표시).

## 사내 네트워크(TLS 프록시) 대응

Windows 인증서 저장소를 PEM 번들(`.cache/system-ca-bundle.pem`)로 내보내 `CURL_CA_BUNDLE` / `REQUESTS_CA_BUNDLE` 에 자동 설정합니다. 별도 설정 없이 동작합니다.
