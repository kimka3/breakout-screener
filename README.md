# 돌파 스크리너

**S&P 500(약 500종목) + KOSPI 200(약 200종목) + KOSDAQ 150(150종목)** 을 대상으로 다음 세 조건을 동시에 만족하는 종목을 찾습니다.

1. **120일 이동평균선 상향 돌파** — 전일 종가 ≤ 전일 MA120, 당일 종가 > 당일 MA120
2. **거래량 급증** — 돌파 당일 거래량 ≥ 직전 5거래일(1주일) 평균 거래량 × 2
3. **돌파 유지** — 현재가(기준 거래일 종가)도 여전히 MA120 위

웹에서는 **120일선 돌파**와 **10개월선 장기 돌파**를 별도 시트로 표시합니다. 각 시트의 시장 선택, 정렬, 카드/표 보기 상태는 독립적으로 유지됩니다. 두 시트 모두 S&P 500, KOSPI 200, KOSDAQ 150을 검사합니다.

## 10개월선 장기 돌파

`--with-monthly`를 추가하면 마지막으로 마감된 **달력 월** 하나에 대해 다음 조건을 모두 검사합니다. 실행 중인 달의 월봉은 사용하지 않습니다.

실시간 실행에서는 **각 시장의 현지 날짜**로 마감 월을 결정합니다. 예를 들어 한국 시간이 9월 1일이어도 미국이 아직 8월 31일 장중이면 미국은 7월을, 한국은 8월을 판정합니다. 명시적인 `--date`는 입력한 날짜의 직전 달을 판정하는 과거 조회 규칙입니다.

1. 기준월 말 종가 **> 해당 월의 10개월 단순이동평균**. 이동평균에는 기준월을 포함한 10개 월말 종가를 사용합니다.
2. 직전 **6개월 각각의 월말 종가 < 각 월의 10개월 단순이동평균**. 이평선과 같은 가격은 '아래'로 보지 않습니다.
3. 기준월 총거래량 **> 직전 3개월의 월 총거래량 산술평균**. 기준월은 평균에서 제외하며, 같은 거래량은 통과하지 않습니다.

예를 들어 **2026-09-13**에 실행하면 기준월은 **2026년 8월**입니다. 8월 종가가 10개월선 위이고, **2~7월**의 종가가 각각 당시 10개월선 아래여야 합니다. 추가로 **8월 총거래량 > (5월 총거래량 + 6월 총거래량 + 7월 총거래량) / 3**이어야 합니다. 거래일당 평균이 아닌 월 총거래량 세 개의 평균입니다. 필요한 네 달의 거래량이 결측·음수·무한대이면 판정 불가로 제외합니다. 직전 3개월 총거래량이 모두 0이면 8월 거래량이 양수일 때 통과하며 배수는 계산할 수 없어 비워 둡니다. 9월 중 가격이 이평선 아래로 내려왔더라도 8월 확정 신호에 추가적인 유지 조건을 적용하지 않습니다. 일봉 옵션 `--ma`, `--vol-window`, `--vol-mult`, `--lookback`, `--no-hold`는 이 고정된 월봉 규칙을 바꾸지 않습니다.

기본 가격 기준은 기존 일봉과 같은 수정주가(`adj`)입니다. 일별 수정계수를 OHLC에 적용한 뒤 월봉을 집계하고, 거래량은 원본 일별 거래량을 월별 합산합니다. `--price-basis raw`는 두 시트에 함께 적용됩니다. 최소 16개월의 연속된 월봉이 있어야 직전 6개월의 10개월 이동평균까지 평가할 수 있습니다. 웹에는 월봉 차트와 직전 6개월의 종가·이동평균 비교값이 표시됩니다.

월봉 카드의 판정표와 차트에는 **최신 완료 일봉의 현재가와 날짜**를 함께 표시합니다. 판정표에는 판정월 실제 종가 대비 현재 실제 종가의 **월말 대비 수익률**도 표시합니다. 이 수익률은 배당·액면분할을 반영한 총수익률이 아닙니다. 차트의 수평 가격선은 선택한 수정주가/원본 가격 기준과 같으며, 실제 종가가 다르면 함께 표시합니다. 진행 중인 월의 캔들을 확정 월봉에 추가하지 않습니다. 현재가는 참고용으로, 월봉 신호 판정에는 사용하지 않습니다. 실시간 호가가 아닌 실행 시 확보한 마지막 완료 일봉이며 `--date` 이후의 가격은 표시하지 않습니다.

```bash
python sp500_breakout.py --lookback 20 --with-monthly \
  --html report.html --out breakouts.csv --monthly-out monthly_breakouts.csv
```

기존 일봉 CSV와 장기 월봉 CSV는 독립적으로 생성합니다. 0건이어도 헤더가 있는 CSV를 기록합니다. 장기 기준월의 이력이 부족하거나 데이터가 유효하지 않은 종목은 제외 수를 표시하고, 선택한 시장을 전혀 평가할 수 없거나 월봉 데이터에 광범위한 누락이 발견되면 실행을 실패 처리해 보고서를 갱신하지 않습니다.

월봉 판정에 필요한 16개월 동안 같은 시장의 다른 종목에서 확인된 거래일을 대조해 가격 이력이 누락된 종목을 제외합니다. 거래정지 등으로 가격이 없는 종목도 판정에서 제외될 수 있습니다. 이는 공급자 시세끼리의 정합성 검사이며, 모든 종목에서 동시에 누락된 거래일은 이 방식만으로 검출할 수 없습니다. 거래소의 공식 거래일 달력과 원시 시세 전체를 대조한 결과는 아닙니다.

## 실행

```bash
python sp500_breakout.py
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--ma` | 120 | 이동평균 기간(거래일) |
| `--vol-window` | 5 | 직전 평균거래량 산출 기간(거래일) |
| `--vol-mult` | 2.0 | 거래량 배수 기준 |
| `--lookback` | 1 | 최근 N 거래일 내에 발생한 신호를 검색 |
| `--date` | 최신 | 기준일 `YYYY-MM-DD`까지의 가격으로 계산. 당시 구성종목·재무정보를 복원하지 않음 |
| `--price-basis` | adj | `adj`=수정주가 기준, `raw`=종가 그대로 |
| `--tickers` | - | 쉼표 구분 티커 목록. `--market sp500`, `kospi200` 또는 `kosdaq150` 필수 |
| `--refresh-list` | - | 구성종목 목록 강제 갱신 |
| `--out` | breakouts.csv | 결과 CSV 경로 |
| `--html` | - | 휴대폰용 HTML 리포트 생성 (경로 생략시 `report.html`) |
| `--summary` | - | 실행 상태와 주요 신호를 담은 텍스트 요약 파일 경로 |
| `--no-cache` | - | 시세 캐시를 무시하고 새로 받기 |
| `--no-hold` | - | 3번 조건 해제 (돌파 후 밀려난 종목도 포함) |
| `--market` | all | `all` / `sp500` / `kospi200` / `kosdaq150` |
| `--with-monthly` | 꺼짐 | 10개월선 장기 돌파를 함께 검사하고 독립 시트로 표시 |
| `--monthly-out` | monthly_breakouts.csv | 장기 돌파 CSV 경로 (`--with-monthly` 사용 시) |

예시:

```bash
python sp500_breakout.py --lookback 5 --vol-mult 1.5
python sp500_breakout.py --market sp500 --tickers AAPL,MSFT,NVDA
python sp500_breakout.py --market kospi200 --tickers 005930,000660
python sp500_breakout.py --market kosdaq150 --tickers 196170,247540
python sp500_breakout.py --lookback 20 --html report.html --out breakouts_20d.csv --summary summary.txt
```

`--ma`, `--vol-window`, `--lookback`은 양의 정수이고, `--vol-mult`는 유한한 양수여야 합니다. `0`, 음수, `NaN`, 무한대 등 유효하지 않은 조건은 실행 전에 거부합니다. 직접 지정한 티커에는 선택한 시장의 거래일·통화·티커 변환 규칙을 적용하며, 해당 지수의 구성종목인지는 확인하지 않습니다.

**`--date`는 과거 가격 구간을 다시 계산하는 기능입니다.** 구성종목은 현재 조회한 목록(또는 캐시된 목록), PER·선행 PER·EPS는 현재 조회값을 사용합니다. 과거 기준일 이후의 액면분할·배당이 현재 수정주가에 반영될 수도 있습니다. 당시 투자 가능 종목과 당시 알려진 정보를 복원하는 시점 일치 백테스트로 해석하면 안 됩니다.

## 휴대폰에서 보기

```bash
python sp500_breakout.py --lookback 20 --html
```

두 개의 HTML이 생성됩니다.

- `report.html` — 브라우저에서 바로 열 수 있는 단독 파일
- `report.artifact.html` — 기존 호환 파일명으로 제공하는 삽입용 HTML 조각. 표시 제목은 '돌파 스크리너'입니다.

게시하면 휴대폰 브라우저에서 열리는 링크가 나옵니다. 종목별로 돌파일·현재 가격과 MA, 거래량, 일봉 차트를 보여 줍니다. 차트는 최근 70거래일을 기본으로 하며, 그보다 오래된 돌파 신호를 표시할 때는 해당 돌파일이 포함되도록 구간을 늘립니다(확보한 이력이 더 짧으면 가능한 구간만 표시). 거래량 스트립은 돌파일 봉만 주황색이고, 차트를 문지르면 그날 값이 표시됩니다. 카드/표 보기와 최근순/거래량배수순 정렬을 전환할 수 있습니다.

가격과 MA를 같은 기준으로 비교하도록 리포트의 주된 가격은 선택한 신호 기준가입니다. 기본 `adj`에서는 `Adj Close / Close` 비율로 시가·고가·저가·종가를 맞춘 수정 일봉을 그리고, 원본 `Close`는 보조 정보로 따로 표시합니다. `raw`에서는 원본 OHLC를 사용합니다. 거래량은 원본 거래량을 사용합니다.

디자인이나 항목을 바꾸려면 `report_template.html` 을 고치면 됩니다. 스크립트가 `/*__DATA__*/null` 자리에 결과 JSON 을 주입하는 구조입니다.

시세는 `.cache/` 에 6시간 캐시되므로 리포트만 다시 뽑을 때는 재다운로드하지 않습니다.

## 자동 실행

GitHub Actions 가 매일 `21:57 UTC`(= 다음날 `06:57 KST`)에 스크리너 실행을 예약해
두 스크리너를 실행하고 결과를 `gh-pages` 브랜치로 배포합니다. PC 를 켜두지 않아도 갱신됩니다. 장기 시트의 기준월은 새 달이 시작될 때 다음 확정 월봉으로 바뀝니다.

- 워크플로: `.github/workflows/daily-schedule.yml`
- 결과 페이지: https://kimka3.github.io/breakout-screener/
- 수동 실행: 저장소 **Actions** 탭 → **Daily breakout screen** → **Run workflow**

예약 시각은 미국장 정규장 마감(서머타임에는 05:00 KST, 겨울에는 06:00 KST) 이후,
한국장 개장(09:00 KST) 이전입니다. 실제 시작은 GitHub 대기열에 따라 늦어질 수 있으므로
06:57 실행이나 개장 전 갱신을 보장하지 않습니다. 데이터 공급자의 갱신 시각도 별개이므로
리포트의 **기준 거래일과 생성 시각**을 함께 확인해야 합니다.

분 단위를 정각에서 어긋내 둔 것은 의도적입니다. GitHub 예약 실행은 정각에
요청이 몰려 대기열이 길어지고, 그만큼 실제 실행이 밀립니다.

예약 실행은 먼저 오프라인 단위 테스트를 통과한 뒤 시세를 수집합니다. HTML·CSV·요약 파일이 비어 있지 않은지 확인하고 배포합니다. 조건 충족 종목이 0건이어도 CSV는 헤더를 포함해 생성합니다. 반면 선택한 시장 중 하나라도 평가할 수 있는 시세가 전혀 없으면 실행을 실패 처리하고 새 결과를 배포하지 않습니다.

`push`와 `pull_request`에서는 `.github/workflows/tests.yml`이 단위 테스트만 실행합니다. 이 검증에서는 시세 스캔, Pages 배포, 텔레그램 알림을 실행하지 않습니다. 로컬에서도 동일하게 확인할 수 있습니다.

```bash
python -m unittest discover -s tests -v
```

> 클라우드 실행은 GitHub Actions 만 가능합니다. Claude 클라우드 루틴은
> 아웃바운드 허용 목록에 패키지 저장소와 Anthropic API 만 있어
> 야후·네이버·삼성자산운용 데이터 API가 `403 CONNECT` 로 막힐 수 있습니다.

## 설계 시 판단한 부분

- **"돌파"** 는 단순히 MA 위에 있는 상태가 아니라 *전일 아래 → 당일 위* 로 교차한 날만 잡습니다. 지속적으로 위에 있던 종목은 걸리지 않습니다.
- **"직전 1주일 평균거래량"** 은 돌파 당일을 **제외한** 직전 5거래일 평균입니다. 돌파 당일을 포함하면 급증분이 분모에 섞여 거래량 배수가 작아지고 판정이 달라집니다.
- **기준가**는 기본적으로 수정주가(Adj Close)를 씁니다. 액면분할·배당으로 생기는 인위적 갭이 가짜 돌파 신호를 만드는 것을 줄이기 위해서입니다. 수정주가가 없거나 사용할 수 없는 값이면 원본 종가로 조용히 대체하지 않습니다. 원본 종가로 판정하려면 `--price-basis raw`.
- 거래량 배수는 `>=` 기준입니다. "2배 초과"로 엄격히 하려면 `--vol-mult 2.001` 처럼 주면 됩니다.
- **돌파 유지**는 *현재 시점에 MA120 위에 있는가*만 봅니다. 돌파 이후 한 번도 이탈하지 않았는지는 따지지 않습니다. `--lookback 1` 로 쓰면 돌파일이 곧 현재일이라 이 조건은 자동으로 충족됩니다.
- **CSV 가격 기준**: 기존 `close` / `last_close`는 돌파일·기준 거래일의 원본 `Close`이며, `return_since_%`도 두 원본 종가의 변화율입니다. 추가된 `signal_close` / `last_signal_close`는 선택한 신호 기준가이고, MA·`above_ma_%`·`last_above_ma_%`는 이 기준가로 계산합니다. 따라서 원본 종가 변화율을 수정주가 수익률이나 배당 포함 총수익률로 해석하면 안 됩니다. `bars_since`는 돌파 후 경과 거래일입니다.
- **시장은 따로 계산합니다.** 거래일 달력과 통화가 다르므로 기준 거래일·가격 표기(달러 2자리 / 원화 정수)를 시장별로 나눠 들고 갑니다. 리포트 상단 탭으로 전환합니다.
- **장중 미완성 봉은 제외합니다.** 해당 시장의 장 마감 시각 전이면 당일 봉을 버립니다. 거래량이 덜 쌓인 봉을 그대로 쓰면 거래량 급증 판정이 왜곡됩니다.
- **KOSPI 200 구성종목**은 네이버 금융에서 받습니다. `pykrx`(KRX 직접 조회)는 사내 프록시 인증서 검증에서 실패합니다.
- **KOSDAQ 150 구성종목**은 삼성자산운용의 KODEX 코스닥150(2ETF54) 공개 PDF 구성내역에서 받습니다. 현금 행을 제외한 고유 종목이 정확히 150개일 때만 캐시하고, 불완전한 응답은 사용하지 않습니다. 이는 KRX의 유료 지수 구성정보 파일이 아니라 지수를 추종하는 ETF의 공개 포트폴리오라는 한계가 있습니다.
- **한국 종목은 후행 PER 이 없습니다.** 야후가 KOSPI 200·KOSDAQ 150 종목에 trailingPE·EPS·섹터를 주지 않아 선행 PER 만 표시되고, 섹터 자리에는 시장명이 들어갑니다.
- **캐시 파일이 읽히지 않으면 새로 받습니다.** 사내 DLP 에이전트가 `.cache/` 의 CSV 를 암호화해 두는 일이 있어(헤더가 `SCDSA...` 바이너리로 바뀜) 읽기 실패를 캐시 미스로 처리합니다.
- **다운로드 실패 종목은 리포트에 표기합니다.** 야후가 대량 요청 중 일부 종목을 간헐적으로 거부하는데, 조용히 빠지면 신호를 놓쳐도 알 수 없습니다.
- **생성 시각은 한국 시간(KST)으로 찍습니다.** GitHub 러너는 UTC 라 `datetime.now()` 를 그대로 쓰면 9시간 어긋납니다.
- **기준 거래일**은 전 종목 마지막 봉의 *최빈값*으로 잡습니다. 최댓값을 쓰면 남들보다 하루 앞선 봉을 가진 한두 종목 때문에 헤더 날짜가 실제 데이터보다 앞서게 됩니다(2026-09-03 실행에서 실제 발생). 날짜가 다른 종목 수는 콘솔과 리포트 헤더에 표기됩니다.
- **PER** 은 조건을 통과한 종목에 대해서만 조회합니다(종목당 1회 요청). 500종목 전체를 받으면 느리고 차단당하기 쉽습니다. `per` 는 최근 12개월 실적 기준, `forward_per` 는 예상 실적 기준이며, 최근 12개월이 적자면 `per` 이 비고 `eps` 가 음수로 나옵니다 (리포트에는 "적자"로 표시).
